# Language Conversion

这个技能内部用了一套学习科学术语（根因节点、Newman 层级、间隔回访 R1~R5、ZPD、Schema、元认知 L0~L5）来做诊断与追踪。这些术语对家长、尤其对孩子完全不可读。

本文件规定**两层语言**的边界：

- **内部层**（frontmatter 字段、Tasks、总结数据表）：用术语，方便程序聚合和长期追踪。
- **用户可见层**（正文、callout、🪞 回顾、家长建议、周月年报正文）：一律用自然中文，**禁止出现下列术语**。

## 禁用术语清单

这些词**不允许出现在任何正文（孩子或家长能读到的地方）**。以"一般家长会感到陌生或学术"为标准筛选——能读懂的中文常用词（如"回访"、"掌握"）不禁。

| ❌ 禁用词 | ✅ 替换说法（按语境选） |
| --- | --- |
| 根因 / 根因节点 | "这一道真正考的是什么" / "这类题的核心" / "这几道题的共同难点" |
| 层级 / L1 / L2 / L3 / L4 / L5 | 不出现数字层级；用自然描述，见下面的层级→自然语言表 |
| Newman | 直接不用，替换成自然分类 |
| 入队 / 出队 / 到期 / 队列 | "加进复习清单里" / "今天要再做一遍" / "从清单移出去" |
| R1 / R3 / R7 / R30 / R90 | 用天数（明天 / 3 天后 / 一周后 / 一个月后 / 三个月后） |
| 重置 | "这块我们再练一遍" |
| 元认知 | "回头想想" / "复盘" / "自己讲一遍" |
| 元认知等级 L0~L5 | 不出现等级数字；用描述："开始会说方法了" / "开始能讲为什么选这个方法了" |
| Schema / schema 成长 | "知识点之间开始连起来了" / "这几个概念她通了" |
| ZPD / 最近发展区 / ZPD 漂移 | "现在题目对她来说偏简单 / 正好 / 偏难" |
| 双轴诊断 | 不需要提 |
| CPA / 具象-图示-符号 | 不需要提；直接说具体动作："搭积木看一下" |
| retrieval mastery | "长期记得住的比例" / "过几天回来还会做的比例" |
| 条目 ID / `2026-04-18-a` | 不出现在正文；内部使用 |
| 认知阶段 / 阶段 A~E | 用年龄/年级自然叙述 |
| mastered | "掌握了" / "学会了" |

## 允许的中文常用词

以下词**虽然是技能内部有对应机制**，但在中文语境里家长能秒懂，**允许出现在正文**：

| ✅ 允许词 | 场景 |
| --- | --- |
| 回访 / 回访题 | "本次回访题处理情况" / "这道题进入回访清单" |
| 掌握 / 学会 / 稳固 | "这个知识点学会了" / "这条已经掌握了" |
| 薄弱点 / 薄弱 | "这段时间的薄弱点" |
| 反思 / 回顾 / 复盘 | 🪞 我的回顾

## 错误层级 → 自然语言

内部我们按 Newman 把错分成 L1~L5 五层。用户可见层用下面四类（合并 L1+L2 为"没看懂"）：

| 内部层级 | 用户可见说法 | 例子 |
| :---: | --- | --- |
| L1 读题 | **题目没看清** | 把"多"读成"少"、漏条件 |
| L2 理解 | **题意没完全懂** | 不知道这道题到底要算什么 |
| L3 转换 | **方法选错了** | 该用 V=Sh 却列了 V=abc |
| L4 执行 | **算错了** | 小数进位漏了 |
| L5 编码 | **算对了，写错了** | 结果对，但单位漏了 |

## 用户可见 callout 类型 vs 技能标注

| 情况 | callout 类型 | 标题起法 |
|---|:---:|---|
| 完全正确 | `success` | "✅ {{题目简述}}" |
| 大方向对但某处不完整 | `warning` | "◐ {{题目简述}}" |
| 错 | `failure` | "❌ {{题目简述}}" |

**callout 标题不要写"根因：维度感知"**。可以写成 "❌ 表面积写成了 a³"（直接陈述错在哪）。

技术分类通过 frontmatter 的 tag 和条目 metadata 保留：

```yaml
# 批改记录 frontmatter
tags:
  - 批改/{{昵称}}
  - 根因/{{节点}}    # ← 技术标签，留给程序聚合
  - 层级/L{{N}}      # ← 同上
```

但正文 callout 标题直接用自然语言描述错误现象。

## 回访题的自然描述

错题进入回访队列后，**Markdown 正文不写"R1 到期"**。改成：

- 第一次到期提示："明天再来一道类似的，不一样的数字和情境，看你还能不能做对。"
- 连续通过一次："做对了！过 3 天再见一次。"
- 连续通过三次："三次都对，这道题算学会了，以后见到类似的都不怕。"

队列 metadata（到期日、进度）继续写在 `_回访队列.md` 的表格里——**这个表给家长看的是概览，细节不必暴露**。技能在批改时内部用这个表决定该调哪些题出来。

## 元认知问题的包装

不说"这是元认知训练"。直接在批改记录末尾加一节叫 **🪞 我的回顾** 或 **复盘小问题**，放年龄对应数量的问题（1~5 个），问题本身用孩子能懂的语气。

不要 rubric L0~L5 出现在用户可见层。只在 frontmatter 里记 `回顾质量: L0~L5` 供长期追踪。

## 讲解的语言层

讲解要按孩子年龄写得他/她能读、能听。`grading-rubric.md` 的讲解风格表按年龄分层，技能执行时必须照年龄取语气。

核心原则：
- **用第二人称** ("你这里...")
- **具象多于抽象** (说"8 块小方块" 而不是 "n=2 的情况")
- **避免术语**（"公式里的量"不如说"公式里每个字母分别代表什么，你知道吗"）
- **给孩子留想的空间**（多问"你觉得"，少断言"这是"）
- **避免负面标签**（不写"你常错这个"，写"这块我们再一起练几次"）

## 家长可见的技术概要

家长侧的少量技术词可以保留（他们需要理解技能在做什么），但要放在**家长专属区块**里，和孩子看的区分开。

```markdown
## 💡 家长侧

- **今天可以和孩子做什么**：{{具体动作，3-5 分钟}}
- **睡前问一句**：{{一个开放式问题}}

<!-- 家长技术说明（孩子不用看） -->
> [!note]- 给家长：技能诊断摘要（可选读）
> 这次 3 道错题在技能内部都归到"维度感知"这个概念节点（面积是平方、体积是立方）。按阶段 C 的 CPA 原则，下次练习加入具象操作能更高效。
```

用 `- ` 折叠把技术说明藏起来，点开才看得到。

## 在模板里的应用原则

所有 Markdown 模板（`summary-templates.md` 定义）都按下面两层写：

1. **frontmatter**：完整技术元数据
2. **正文**：只用本文件允许的自然语言，杜绝上面禁用词清单里的所有术语

任何模板如果在正文里出现了禁用词，视为**模板违规**，需要立即改。
