# Image Generation

本技能通过 `baoyu-danger-gemini-web` 技能调用 Gemini Web API 生成配图。每次批改在**批改主图、错题图、周期总结图**三个位置各生成一张，让孩子对抽象概念有具象的"看一次"，提升理解和记忆。

## 为什么要配图

以一个典型的根因"维度感知"为例（示例）。孩子反复在 cm²/cm³、n²/n³、公式 a³ vs 6a² 上出错，根源是脑中"几维 ↔ 次方"的对应还没锚到具象。Bruner 的 CPA 原则里最关键的一步是**具象（Concrete）**——让孩子"看见"这件事。

文字讲解是 A 层（抽象符号），家长侧活动是 C 层（具体实物），配图是中间的 **P 层（Pictorial 图示）**。三层一起才是 CPA 闭环。单独看讲解和做活动，中间缺了承接，抽象难落回具体。

本技能默认每次批改生成：
- **1 张批改主图**：本次主根因的概念可视化
- **N 张错题图**：每道错题一张对比/具象图（N = 本批错题数）
- **1 张总结图**：周 / 月 / 年总结触发时各一张

## 调用方式

baoyu-danger-gemini-web 的 CLI 入口是 `/Users/yr/.claude/skills/baoyu-danger-gemini-web/scripts/main.ts`。基本命令：

```bash
npx -y bun /Users/yr/.claude/skills/baoyu-danger-gemini-web/scripts/main.ts \
  --prompt "{prompt text}" \
  --image "{output path}.png" \
  --model gemini-3-pro
```

**首次或 cookie 过期**时必须先运行 `--login` 刷新 cookie：

```bash
npx -y bun /Users/yr/.claude/skills/baoyu-danger-gemini-web/scripts/main.ts --login
```

如果生成命令报 `SECURE_1PSIDTS could get expired` 或 `socket connection was closed`，大概率是 cookie 过期。跑一次 login 再重试。

每张图约 10-20 秒，偶尔失败后重试一次通常能成。

## 图片存储

所有图片存在 Obsidian 档案根目录下的 `图片/` 子树。命名用**稳定唯一的 ID**，这样 Obsidian wikilink `![[xxx.png]]` 能按文件名自动解析。

```
<档案根目录>/图片/
├── 批改/
│   └── {YYYY-MM-DD-HHMM}.png              # 对应批改记录文件名
├── 错题/
│   └── {条目 ID}.png                       # 条目 ID 如 2026-04-18-a
└── 总结/
    ├── 周报/{YYYY-Www}.png
    ├── 月报/{YYYY-MM}.png
    └── 年报/{YYYY}.png
```

写入用 `obsidian create path="..." --file`（若 CLI 支持二进制）或直接 cp 到 vault 路径（vault 路径用户已确认）。目前实现：先用 bash 把临时文件 cp 到 vault 下对应路径。

## 何时生成

| 图类型 | 何时生成 | 触发位置 | 频率控制 |
|---|---|---|---|
| 批改主图 | 每次批改 | Step 5 写回前 | 1 张/次 |
| 错题图 | 每道新错题 | Step 5 写回前 | N 张/次 |
| 总结图 | 周/月/年总结触发 | Step 7 总结后 | 1 张/周期 |

**回访题**（情境变式复现）不额外生成图——引用原错题条目里的图即可，避免重复。

**同根因反复错题**可以考虑复用图片（用同一图片文件引用多条错题条目），但默认仍每道错题一张专属图。专属性胜过复用。

## 提示词模板

### 批改主图（本次主根因概念图）

```
小学{年级}数学教学示意图。主题：'{主根因节点}'——{简短概念描述}。

要求：
- 画面{要素描述，如"分三栏并排" / "用立方体拼图" / "对比图"}
- 每栏标注 {具体标注，含中文}
- 风格：教科书插图、颜色清新、中文字幕清晰、背景干净
- 不要水印或 logo
```

示例（9-11 岁孩子，主题"维度感知"）：

```
小学五年级数学教学示意图。主题：'维度感知'——二维面积与三维体积的区别。

画面分三栏并排。
左栏：一根线段，下方标注'长度 · 一维 · 单位 cm'。
中栏：一个正方形（由 3×3 的小格子组成），下方标注'面积 · 二维 · 单位 cm²'。
右栏：一个立方体（由 3×3×3 的小方块组成），下方标注'体积 · 三维 · 单位 cm³'。
风格：教科书插图、颜色清新、中文字幕清晰、背景干净、不要水印。
```

### 错题图（错 vs 对 · 具象对比）

```
小学{年级}数学错题对比图。主题：{错题核心问题}。

左半：{错误的做法或概念}，下方或内部标注'错在哪'的关键点。
右半：{正确的做法或概念}，用{具象元素}帮助理解。
顶部大标题{概括性一句话}。
风格：教科书插图、彩色清新、中文清晰、背景干净、不要水印。
```

### 总结图（周期的"成长画面"）

```
小学{年级}孩子的数学学习成长可视化。周期：{YYYY-Www / YYYY-MM / YYYY}。

画面要素（选 2-3 种组合）：
- 一条从低到高的成长曲线（代表正确率或元认知等级的提升）
- 几个概念节点的可视化（稳固 = 绿色、挣扎 = 黄色、新浮现 = 蓝色）
- 一棵小树（每个概念稳固时添一片叶子）
- 4 个维度的小图标（Schema / ZPD / 元认知 / 回访）

要求：
- 不要出现具体成绩数字（避免制造分数焦虑）
- 色调温暖
- 中文标签
- 不要水印
```

## 阶段适配的风格差异

按 `pedagogy-by-stage.md` 的阶段调整视觉风格：

| 阶段 | 风格基调 | 具象程度 | 标签语气 |
|:---:|---|:---:|---|
| A · 一~二年级 | 卡通、鲜艳、角色化 | 高，全具象 | 拟人化（"小方块宝宝"） |
| B · 三年级 | 插图 + 图示 | 高 | 简单叙述 |
| C · 四~五年级 | **教科书插图**、对比清晰 | 中 | 直接说明 |
| D · 六年级 | 图示为主、少插图 | 中低 | 精准 |
| E · 初中 | diagram、公式、少装饰 | 低 | 正式 |

提示词里明确写"风格：{阶段对应}"，让 Gemini 生成符合年龄的画面。

## 在 Markdown 里的嵌入

Obsidian wikilink 语法：

```markdown
![[2026-04-18-0142.png|600]]

说明：batch main image
```

`|600` 是显示宽度（像素）。默认 400-600px 合适批改记录正文；总结图可用 800px。

### 批改记录里的位置

```markdown
# 📝 {日期} 数学批改

> [!abstract] 整体情况
> ...

![[{YYYY-MM-DD-HHMM}.png|600]]
> 本次主根因 **{主根因}** 的概念图。建议打开图片让孩子看一眼再往下讲。

## 📋 逐题速览
...
```

### 错题 callout 里的位置

```markdown
> [!failure] ❌ {错误类型} · L{层级} · 根因：{节点}
> **孩子作答**：...
> **正确**：==...==
>
> ![[{条目 ID}.png|500]]
>
> **错在哪**：...
```

### 错题本条目里同样引用：

```markdown
## {日期} · L{层级} · 根因：{节点}

> [!failure] {标题}
> ...
>
> ![[{条目 ID}.png|500]]
>
> ...
```

同一张错题图在批改记录和错题本里**两处引用同一个文件**，Obsidian 会正确显示。

### 总结里的位置

```markdown
# 📆 {周期} 周报

![[{周期}.png|800]]

> [!abstract] 整体状况
> ...
```

## 失败处理

- Cookie 过期 → 自动跑 `--login` 刷新，再重试一次。如果 login 也失败，跳过配图（批改流程继续），在批改记录里放一行 `> [!note] 本次配图生成失败（cookie 刷新未完成），请稍后手动重试` 并告知用户。
- Gemini 返回空或质量不达标 → 重试一次用更具体的提示词；仍不行就跳过该张，标记"待补图"。
- 超过 5 张连续失败 → 停止本次批改的图片生成，走纯文本流程，完整批改记录里加显著的 `⚠️ 配图流水线异常` 提示。
- 图片文件超过 2 MB（单张）→ 这通常是正常的 Gemini 输出，Obsidian 能处理，但可以用 `sips -Z 1200` 压一下：

```bash
sips -Z 1200 "{path}.png" --out "{path}.png"
```

## 成本与时间预算

单批次生成量（以一次 13 道错题的体量为例）：

- 1 张批改主图 + 13 张错题图 = **14 张**
- 时间：约 3~5 分钟（串行，10-20s / 张）
- 成本：由 Gemini Web API 决定，单张约等于一次网页对话的计算量

若一次批改错题太多（> 10），可以考虑：
- 只生成根因前 3 位的错题图（最高优先级的主薄弱），其余条目先不生成
- 在批改记录里标记哪些条目有图、哪些没有
- 等 schema 成长稳定后再补图

**默认规则**：错题 ≤ 8 时每道都生成；> 8 时只给根因图谱中前 5 的节点生成代表图。

## 技能协作流程

```
prism-child-homework (Step 5 写回前)
    ↓
  决定要生成哪些图 (批改主图 + N 张错题图)
    ↓
  按模板生成 prompt
    ↓
  调用 baoyu-danger-gemini-web CLI
    ↓
  文件落地到 tmp/
    ↓
  cp 到 Obsidian 档案根目录下的 图片/xxx 路径
    ↓
  在批改记录 / 错题本 / 总结 Markdown 中嵌入 ![[xx.png]]
    ↓
  obsidian-cli 写回 Markdown
```

## 注意

- 不要在图上写"正确答案"的最终数字（比如"1200 cm³"），避免孩子看图秒出答案没动脑。图的作用是**帮助理解概念**，不是替代解题。
- 对错题图，画面应该展现**两种做法的对比**和**根因的具象**，不直接揭示最终答案。
- 对批改主图和总结图，主要呈现**概念结构**或**成长轨迹**，不包含题目数据。
