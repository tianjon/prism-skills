# prism-child-homework

## Overview

批改照片里的数学作业，用**孩子年龄能读懂的语言**讲解错题，生成针对性练习，额外附一节**数学建模专题课**（向奥赛靠齐的拔高内容），并维护 Obsidian 中的长期档案。技能内部把教学法和儿童认知心理学结构化地嵌入诊断与练习设计，但写给孩子和家长看的文字里不出现任何学术术语。

内部分析维度（对用户不可见）：

- 年龄 → 认知阶段 → 方法矩阵（Piaget / Vygotsky / Bruner CPA / 人教课标）
- 错题双轴诊断：Newman 层级 × 概念根节点
- Ebbinghaus / Bjork 的间隔回访队列
- Schoenfeld / Polya 的反思训练
- 多维度总结：概念成长 × 难度匹配 × 反思深度 × 长期记忆

写给孩子 / 家长看的层面一律用自然中文。转换规则见 `references/language-conversion.md`。

本技能 prompt-first。视觉识别与诊断靠 Claude 自身能力；所有持久状态通过 `obsidian-cli` 技能持久化在 Obsidian 中。

## When to Use

- 批改、检查、看看 孩子已经做完的数学作业（通常附带照片）
- 讲解某道做错的题目或整张作业
- 根据孩子最近的薄弱点生成练习题
- 查看或生成本周 / 本月 / 今年的作业情况总结
- 建立或更新孩子的作业档案

不要用于：

- 非数学科目（语文、英语等暂未支持，请明确拒绝并告知未来扩展方向）
- 与档案无关的一次性数学问答（直接回答即可，无需写入 Obsidian）

### 用户触发短语（用于识别意图）

技能识别下列触发短语并路由到对应动作。识别时不要求精确匹配，句意等价即可。

| 意图 | 常见触发 | 动作 |
|---|---|---|
| 批改作业 | "批改"、"检查这份作业"、"看看这个对不对"、附带作业照片 | 走完整 8 步 Workflow |
| 讲解单题 | "这题为什么错"、"帮我讲一下第 3 题" | 走 Step 3（只批改 + 讲解），不一定要生成练习 |
| 生成练习 | "出几道练习"、"给她做点类似的题"、"针对薄弱点练一练" | 走 Step 1 + Step 4，不需要照片 |
| 查看总结 | "这周她怎么样"、"看下本月总结"、"生成周报" | 走 Step 7 |
| 重新生成图 | "第 X 题的图不满意，重画"、"换一张图" | 只调用 `baoyu-danger-gemini-web` 重生成指定图（其他流程跳过） |
| 更新档案 | "她升到六年级了"、"出生年月是 xxxx-xx-xx"、"改一下档案" | 只更新 `孩子档案.md` 相应字段，不产生新批改记录 |
| 首次建档 | 没有档案却提到孩子学习 | 阻塞式问昵称、出生年月、年级、根目录，建档 |
| 多孩切换 | "这次是另一个孩子的作业" | 阻塞式询问应切到哪个档案根目录；若不存在则走首次建档 |

## Hard Constraints

### 持久化与排版

- 所有 Obsidian 读写必须通过 `obsidian-cli` 技能，禁止直接操作文件系统。
- 写入 Obsidian 前必须调用 `obsidian-markdown` 技能校准排版：callout、highlight、inline code、task list、短名 wikilink。不输出素面 Markdown。
- 每次批改必须通过 `baoyu-danger-gemini-web` 技能生成配图：1 张批改主图 + N 张错题图（每道错题一张）。周/月/年总结触发时各生成 1 张总结图。规则见 `references/image-generation.md`。
- **数学符号优先用 Unicode + inline code**（`` `50 × 50 × 4 = 10000 cm³` ``）。以 `\t` / `\n` 开头的 LaTeX 命令会被 `obsidian-cli` 的 `content=` 参数破坏，用 Unicode 替代。
- 写入 Obsidian 的正文一律使用中文。

### 用户可见语言（核心）

- **正文、callout、🪞 回顾、家长侧、周月年报正文** 中 **严格禁止出现**：`根因 / 根因节点 / 层级 / L1~L5 / Newman / 入队 / 出队 / 队列 / 到期 / R1~R5 / 重置 / 元认知 / 元认知等级 / Schema / ZPD / 最近发展区 / 双轴诊断 / CPA / 条目 ID / 认知阶段 A~E / mastered`。
- **允许** 写进正文的自然中文词：`回访 / 回访题 / 掌握 / 学会 / 稳固 / 薄弱点 / 反思 / 回顾`。
- 这些术语的完整清单与翻译规则见 `references/language-conversion.md`。
- 正文一律用自然中文。任何违反此规则的输出视为不合格，必须重写。

### 输出模式（核心）

本技能**每次批改必须同时产出三份文件**，全部落到同一个日期子目录下的三个并列子目录：

- **简洁模式**（`批改记录/YYYY-MM/YYYY-MM-DD/简洁模式/{UNIT_TOPIC}_{INDEX}.md`）
  - 用 **5-callout 套装**（`[!failure]` + 2×`[!tip]` + `[!question]` + `[!success]-`）
  - 讲解 **3 块**：为什么错 / 正确做法 / 验证 3 道（+ 答案）
  - 正确题只打 ✅ 不展开
  - 适合家长快速过一遍孩子情况 / 打印给孩子做
  - 模板在 `references/summary-templates-concise.md`

- **完整模式**（`批改记录/YYYY-MM/YYYY-MM-DD/完整模式/{UNIT_TOPIC}_{INDEX}.md`）
  - 用 **8-callout 套装**（`[!failure]` + 6 讲解块 `[!tip]/[!warning]/[!note]/[!info]` + `[!question]` + `[!success]-`）
  - 讲解 **6 块**：为什么错 / 正确做法 / 举一反三 / 容易混的地方 / 小口诀 / 知识点延伸
  - 正确题有点评 + 知识点延伸
  - 文件末尾含 📊 给家长：技能诊断摘要（根因图谱 / 认知阶段分析）
  - 适合想系统跟踪学习过程、回读历史错题的家庭
  - 模板在 `references/summary-templates.md`

- **数学建模专题课**（`批改记录/YYYY-MM/YYYY-MM-DD/数学建模/{UNIT_TOPIC}_{INDEX}.md`）
  - 承接当日 `UNIT_TOPIC`，把课堂概念推到**奥赛靠齐**的难度，练"把实际情境翻译成数学式子"
  - 必含四块：①建模主题说明 ②建模三步法（抽象→建模→求解/验证）③核心概念讲解 ④**奥赛级练习题**（折叠答案 + 思路）
  - 难度按年龄阶段分级对标奥赛（A · 趣味幼苗组 / B · 希望杯预备 / C · 华杯初赛级 / D · 华杯决赛入门 & AMC 8 预备 / E · AMC 8/10 & 华杯决赛）
  - **超出课标**，允许使用课本尚未正式引入但可以通过具象/画图理解的概念（如抽屉原理、穷举构造、奇偶性、不定方程思想）
  - 正文仍用自然中文，禁用词表同批改记录，不出现"奥赛级别"以外的内部术语（"抽屉原理"等**专有数学名词**允许）
  - 文末短回顾：2 个"建模视角"问题（见 `references/math-modeling-class.md`）
  - 模板与难度矩阵在 `references/math-modeling-class.md`

### 三份文件的关系

- **每次批改必须同时产出三份**（简洁 + 完整 + 数学建模）——少一份即视为不合格
- **档案 / 索引 / 错题本 / 回访队列 / 周月年报 全部共用**，不分模式
- **互相 wikilink**：简洁↔完整末尾互链；数学建模末尾链到简洁 + 完整；完整末尾在"关联"区增加链到数学建模
- 档案 frontmatter 里的 `输出模式` 字段**保留**但**不再决定产出**——仅作为家长主用视图偏好标记（仅对 简洁/完整 二选一生效，不影响建模课）
- 简洁模式和完整模式**内容必须一致**（同样的错题、同样的根因诊断、同样的正确率、同样的回访安排），只在**展开深度**上不同
- 数学建模课**独立于批改诊断内容**：不复述错题，不参与回访队列；只借用当日 `UNIT_TOPIC` 作为建模切入点

### 年龄匹配与上下文载入（核心）

- **每次批改必须先完成下列载入，任何一项失败就停下来解决**：
  1. `obsidian read` 读 `孩子档案.md`，取出 `出生年月`（若有）、`年龄`、`当前年级`、近期薄弱点、过往错题、回访队列、反思成长。
  2. **自动计算并同步年龄**：若档案有 `出生年月`，按今天日期重新算出整数年龄；若和 frontmatter 里的 `年龄` 字段不同，**直接覆盖 `年龄`**（同时写回档案）。若档案只有 `年龄` 没有 `出生年月`，沿用 `年龄` 但在本次回应末尾提醒用户补填 `出生年月`。
  3. **派生认知阶段（不信任缓存）**：用步骤 2 得到的 `年龄` 查 `references/pedagogy-by-stage.md`，直接用派生值覆盖 frontmatter 的 `认知阶段`。存在档案里的 `认知阶段` 字段只是缓存，每次都重新计算。
  4. 用该阶段的参数载入：讲解语气 / 详略 / 练习结构 / 回顾问题深度 / 家长侧建议风格。
  5. 读 `_回访队列.md`，取出到期条目。
  6. 读最近 5~10 份批改记录，获得近况与错题上下文（用 `obsidian search query="类型: 批改记录"` 拿到候选列表）。
  7. 读活跃错题本文件，获得概念节点命中统计（`obsidian search query="类型: 错题条目"`）。
  8. **周期边界检查 · 补齐所有缺失**：比较档案 `上次批改时间` 与今天，逐级找出所有缺失的周期总结（周报 → 月报 → 年报），**全部补齐**而非只补上一个。补齐顺序：先补最老的周报、依次滚到最近，然后月报、然后年报。
- 所有阶段参数（讲解语气、练习题量、变式比例、回顾问题数量）**全部由 `年龄` 查阶段矩阵得出，不可自行选择**。
- **`出生年月` 或 `年龄` 至少有一个必须存在**。优先级：`出生年月` > `年龄` > `年级`。
- 首次运行必须阻塞式询问：孩子昵称、**出生年月**（优先）或年龄、（可选）当前年级、档案根目录。（输出模式不再询问——每次都同时产出简洁 + 完整两份，`输出模式` 字段只用于记录家长主用视图偏好）
- **数据一致性检查**：若 `出生年月` 算出的年龄与 `年龄` 或 `年级` 对应的年龄差 > 2 岁，停下来询问笔误（参见 2025-04-18 苹果案例：用户写 2024 实际是 2014）。

### 诊断口径

- 每道错题内部打两个分析标签（**只放 frontmatter 的 `tags`**，不进正文）：
  - `层级/L1~L5`（Newman：读题 / 理解 / 转换 / 策略 / 编码）
  - `根因/<概念节点>`（跨知识点的深层概念）
- 分类规则见 `references/error-taxonomy.md`。
- 正文中用自然语言描述错在哪、为什么错、怎么改，不出现 "层级"、"根因" 字样。
- 对比档案里的概念节点命中：本次错题若命中既有节点，必须在讲解中点出（自然语言："这类题你上次也在 xxx 这块出过问题"）并用 wikilink 链到旧条目。

**错题 ID 规则**：
- 格式 `YYYY-MM-DD-<letter>`，单日全局唯一（跨批次连续，不按批次重置）
- 前 26 道用 `a~z`；第 27 道起用两字母 `aa/ab/.../az/ba/...`
- 同日不同批次：第二次批改的首个错题接上一次的序号（例如第一次用到 `g`，第二次从 `h` 开始）

### 讲解详略（按模式 + 年龄）

**完整模式**下每道错题的讲解正文必须覆盖**六模块**（深度按年龄调整）：

1. **为什么错**（诊断）：指出真正的卡点
2. **正确做法**（步骤）：每步写清楚 + 为什么
3. **举一反三**（泛化）：1-2 个类似题型 + 识别信号
4. **容易混的地方**（辨析）：近邻概念 + 辨别点
5. **小口诀 / 小规律**（记忆，可选）
6. **知识点延伸**（关联）：课本位置 + 前后衔接

正确题的点评覆盖：**做得好的点** + **知识点延伸**。

**简洁模式**下每道错题的讲解正文只有**三块**：

1. **为什么错**（一两句）
2. **关键规则**（单位换算 / 公式 / 识别信号，**用代码块或短列表**呈现，不用长文字）
3. **3 道验证练习**（同类 1 + 变式 1 + 稍进阶 1）+ 折叠答案

正确题**只打 ✅ 占一行**，不展开。

讲解的语言必须按阶段（由年龄决定）取自 `references/pedagogy-by-stage.md`——详略、人称、颗粒度、复杂度全部查表。**每次批改必须同时产出简洁 + 完整两份批改记录**，落到不同子目录（见 `Output Contract`）。

### 间隔回访

- **每次生成练习题必须先检查到期回访队列**。队列 frontmatter 保留 R1~R5 记号；**用户可见文字一律用"明天 / 3 天后 / 一周后"等自然描述**。
- 回访题在 Markdown 里用 🔁 标记 + 自然语言说明（如"上次 xxx 错过，这次换个情境再试一下"）。
- 写回时更新队列：新增错题追加，已回访按对错推进/重置。详见 `references/retrieval-schedule.md`。

### 反思训练（原"元认知"）

- 批改记录必须在末尾加固定一节 **🪞 我的回顾**（不要写"元认知"字样），按年龄放 1~5 个问题让孩子自答。问题清单见 `references/metacognition-prompts.md`。
- 孩子回答后，技能按 L0~L5 rubric（内部）打分，累计到 `孩子档案.md` 的 `反思成长` 字段（frontmatter）。**等级数字不在正文出现**。

### 安全与边界

- 批改结论必须逐题对应到照片中的题号或位置，不允许凭空捏造题目或答案。
- 手写字迹无法辨认时必须询问用户或标注 `待确认`，禁止猜测。
- 目前仅支持数学。识别到非数学内容时明确拒绝并解释。
- 周 / 月 / 年总结必须幂等：重新生成覆盖旧文件。
- 默认只维护一个孩子的档案。多孩家庭必须通过不同的档案根目录区分。

### 通用性

- 本合约不预设孩子的昵称、具体年龄、具体年级。`苹果`、`小明`、`维度感知` 这些在文档里出现时必须**清晰标注为"示例"**，不是默认值。
- 不预设科目用词：技能现阶段虽然只处理数学，但讲解框架与语言转换规则（`language-conversion.md`）设计时不绑定数学。

### 多孩家庭

- **一个孩子 = 一个档案根目录 = 一份完整档案树**（孩子档案 / 索引 / 回访队列 / 批改记录 / 错题本 / 练习题 / 总结 / 图片）。
- 根目录必须通过**显式不同的子路径**隔离，例如：
  - `教育/家庭作业/苹果/数学/` 和 `教育/家庭作业/小明/数学/`
  - 或 `教育/家庭作业/数学/苹果/` 和 `教育/家庭作业/数学/小明/`
- 不允许在同一根目录下用昵称做字段区分（避免根因图谱 / 回访队列交叉污染）。
- 用户在对话里提到 "另一个孩子" 时，技能必须**先确认**切换到哪个根目录；若不存在就走首次建档。

### 科目扩展路径

本技能架构不绑定数学——所有"讲解六模块 + 按年龄分阶段 + 双轴诊断 + 间隔回访 + 反思训练 + 四维度总结"的机制对任何学科都适用。

当前版本**只开通数学**，因为：
- 识别手写数学作答较其他学科成熟
- 数学错题的根因节点命名已在 `grading-rubric.md` 里有现成清单
- 视觉配图（Gemini）在数学概念图上效果最稳

未来扩展到其他学科时：
- 为新学科增加一份 `references/grading-rubric-<学科>.md`（知识点清单 + 讲解风格）
- 允许档案里 `科目` 字段支持多值
- 在目录树里用 `<学科>/` 子目录分类（如 `教育/家庭作业/数学/` 和 `教育/家庭作业/语文/`）——相当于多学科用类似多孩的方式隔离

## Runtime Policy

- 依赖 Claude 自带的视觉能力识别作业照片，不调用额外 OCR 工具。
- Obsidian 必须处于运行状态且 `obsidian-cli` 可用；否则终止并告知。
- 档案根目录按下列优先级解析：
  1. 用户当前对话中显式提供的路径
  2. `孩子档案.md` 中记录的 `档案根目录`
  3. 环境变量 `$CHILD_HOMEWORK_ARCHIVE_ROOT`
  4. 阻塞式询问用户（首次建档路径）；不得写死
- **首次运行必须阻塞式确认**：孩子昵称、**年龄**、（可选）当前年级、档案根目录。不要静默生成。
- 跨自然周 / 月 / 年边界时，先补齐过期总结，再处理本次作业。

### 环境变量

技能不得在文档或脚本中写死任何个人机器路径。下列变量用于解析绝对/相对位置：

| 变量 | 含义 | 未设置时的行为 |
|---|---|---|
| `CHILD_HOMEWORK_VAULT_ROOT` | Obsidian vault 根的**绝对路径**。用于直接 `ls` / `cp` 等绕过 obsidian-cli 的文件系统操作（图片写入、大文件后备写回、列目录）。 | 回退到 `obsidian vault` 命令查询到的路径。仍无法解析则停止并告知。 |
| `CHILD_HOMEWORK_ARCHIVE_ROOT` | 档案根目录。可以是**相对 vault 的子路径**（如 `教育/家庭作业/数学`）或绝对路径。 | 回退到 `孩子档案.md` 的 `档案根目录`；仍缺失则阻塞式询问用户。 |
| `BAOYU_GEMINI_CLI` | `baoyu-danger-gemini-web` 技能 CLI 入口的**绝对路径**。 | 默认 `$HOME/.claude/skills/baoyu-danger-gemini-web/scripts/main.ts`。若该默认路径不存在则停止配图并告知。 |

引用规则：

- shell 命令里统一写 `"$CHILD_HOMEWORK_VAULT_ROOT"` / `"$CHILD_HOMEWORK_ARCHIVE_ROOT"` / `"$BAOYU_GEMINI_CLI"`；不要在文档里给出 `/Users/<name>/...` 这类绝对示例。
- 组合 vault 绝对路径与相对档案根时用 `"$CHILD_HOMEWORK_VAULT_ROOT/$CHILD_HOMEWORK_ARCHIVE_ROOT"`。
- 档案 frontmatter 写入的 `档案根目录` 字段仍存明文字符串（否则跨会话读不回来）——环境变量只影响运行时解析路径，不影响 vault 内落地内容。

## Output Contract

Obsidian 档案默认目录（所有路径均在 `档案根目录` 之下）：

- `孩子档案.md` — 含 `出生年月`、`年龄`、`年级`、`输出模式`、概念节点命中图谱、反思成长、回访队列指针
- `_索引.md` — 仪表盘
- `_回访队列.md` — 学习队列（活跃错题到期表）
- `批改记录/YYYY-MM/YYYY-MM-DD/简洁模式/{UNIT_TOPIC}_{INDEX}.md` — **每次批改必须产出**，5-callout 套装（3 块讲解）
- `批改记录/YYYY-MM/YYYY-MM-DD/完整模式/{UNIT_TOPIC}_{INDEX}.md` — **每次批改必须产出**，8-callout 套装（6 块讲解 + 正确题点评 + 技能诊断摘要）
- `批改记录/YYYY-MM/YYYY-MM-DD/数学建模/{UNIT_TOPIC}_{INDEX}.md` — **每次批改必须产出**，建模主题 + 三步法讲解 + 奥赛级练习题（折叠答案），模板见 `references/math-modeling-class.md`
- `错题本/{TOPIC}.md` — 按课标知识点一份文件（追加累积）
- `练习题/{UNIT_TOPIC}/{知识点}.md` — 按细分知识点累积归档
- `总结/周报/YYYY-Www.md`、`总结/月报/YYYY-MM.md`、`总结/年报/YYYY.md` — 覆盖式
- `总结/专题/<知识点>-掌握-YYYY-MM-DD.md` — 新建（某概念稳定掌握时）
- `总结/里程碑/反思-YYYY-MM-DD.md` — 新建（反思跃迁时）
- `图片/原始图片/{UNIT_TOPIC}_{INDEX}_{SUBINDEX}.png` — 家长上传的作业照片原件（存档留底）
- `图片/错题/{UNIT_TOPIC}_{知识点}.png` — 每道错题的对比示意图
- `图片/核心知识点图解/{UNIT_TOPIC}_{知识点}.png` — 核心概念图（跨批次共享）

命名占位符：
- `UNIT_TOPIC` = 课本单元主题（`长方体和正方体`、`分数运算`）
- `INDEX` = 当日该单元第 N 次批改（1, 2, …）
- `SUBINDEX` = 单次批改的第 N 张照片
- `TOPIC` = 课标知识点名（`体积与表面积`）
- `知识点` = 细分知识点（`体积单位`、`面积进率`）

行为要求：

- 档案、索引、回访队列、周/月/年总结为**覆盖式更新**；批改记录（含建模课）、错题本、练习题、专题、里程碑、图片为**追加式写入**。
- **每次批改必须同时产出三份文件**（简洁模式 + 完整模式 + 数学建模）——少一份即视为不合格。
  - 简洁 ↔ 完整末尾互相 wikilink；完整末尾在 🔗 关联区额外链到数学建模；数学建模末尾链到简洁 + 完整。
- 每份批改记录（简洁 / 完整）必须包含：整体情况 + 核心知识点图 + 原始照片（折叠） + 逐题速览表 + 逐题讲解（简洁 5-callout / 完整 8-callout） + 🪞 我的回顾 + 🎓 今日家长侧 + 🔗 关联。
- 数学建模文件必须包含：建模主题说明 + 建模三步法讲解 + 核心概念深化 + 奥赛级练习题（≥3 题，折叠答案 + 思路）+ 🔭 建模视角回顾（2 个问题）+ 🔗 关联（链回简洁 / 完整批改记录）。
- 错题本条目必须反向链接到触发它的批改记录（简洁版）。
- 总结生成前必须通过 `obsidian-cli` 列出该周期内的所有批改记录再汇总，不凭记忆。
- 练习题（含建模课内练习）必须附答案与简要思路，放在可折叠 callout 中，答案默认不展开。
- 详细模板：简洁模式见 `references/summary-templates-concise.md`、完整模式见 `references/summary-templates.md`、数学建模课见 `references/math-modeling-class.md`。

## Workflow

### Step 1: 载入上下文（强制）

1. `obsidian read` → `孩子档案.md`。取 `年龄`、`年级`、薄弱点、概念节点命中图谱、反思成长等。**`年龄` 必须存在**——缺失就阻塞式询问并回填。
2. 由 `年龄` 定位 `references/pedagogy-by-stage.md` 的阶段，载入该阶段的参数。
3. `obsidian read` → `_回访队列.md`，筛选到期条目。
4. `obsidian ls` → 最近 1-2 个月批改记录，按时间倒序读 5~10 份，提取正确率序列与近期错题。
5. `obsidian ls` → 活跃错题本目录，读取 frontmatter 与最新条目。
6. 检查周 / 月 / 年边界。跨越则先执行 Step 7 补齐总结。

**首次运行**（档案不存在）：阻塞式询问四项——孩子昵称、**年龄**、（可选）年级、档案根目录。创建档案 + 索引 + 空回访队列三个文件后再继续。

### Step 2: 解析照片

- 对每张照片输出结构化列表：`[题号, 题目原文, 孩子作答, 识别置信度]`。
- 非数学内容或多科目混合 → 停下来确认。
- 置信度低的条目标 `待确认`，由用户补充后再进入批改。

### Step 3: 批改与讲解

- 逐题判定 `正确` / `部分正确` / `错误`。
- **错题打两个内部标签**（只进 frontmatter 的 tags，不进正文）：Newman 层级 + 概念根节点。
- 写讲解——每道错题必须覆盖**为什么错 / 正确做法 / 举一反三 / 容易混的地方 / 小口诀（可选）/ 知识点延伸**六块。详略由年龄决定。
- **正确题也要写点评**——包含"做得好的点" + "知识点延伸"。
- 语气按年龄适配（第二人称、Growth Mindset、避免标签化）。
- 若错题命中档案既有概念节点，在讲解中点出并 wikilink 到旧条目。

### Step 4: 生成练习题（含回访）

按年龄对应阶段分配题量（详见 `references/pedagogy-by-stage.md`）：

- 新题覆盖：同类 + 变式 + 稍进阶（比例按阶段定）
- **回访题**：到期列表 > 0 时挑 1~2 条，按"情境变式"生成（数字、物品都要换）
- 回访题在 Markdown 用 🔁 标注 + 自然语言说明（"上次这类题你卡在 xxx，今天换一种情境再试一下"）
- 答案折叠 callout，默认不展开

### Step 5: 我的回顾（反思训练）

在批改记录正文末尾加一节 **🪞 我的回顾**。按年龄从 `references/metacognition-prompts.md` 取 1~5 个问题。

**两条回写路径**（孩子的回答通过哪条进到档案）：

- **路径 A · 家长代填 Markdown**：首次写入时问题后留 `→ ` 空白，家长陪孩子在 Obsidian 里自己填上。**下一次批改**技能在 Step 1 读当前批改记录时，如果发现上一次的 🪞 回顾里有孩子填的内容，按 L0~L5 rubric 打分，写回 `孩子档案.md` 的 `反思成长`，再走本次批改。
- **路径 B · 孩子在对话里当场答**：如果孩子在**当前会话**里已经口头或文字回答了上次的 🪞 问题，技能把回答直接填入上一次批改记录对应位置（`obsidian read → 修改 → obsidian create overwrite`），并立即打分、更新档案。然后再处理本次新批改。

两条路径都必须把 L 等级写进 frontmatter 的 `反思成长.近30天平均等级`，对孩子/家长不展示。本次批改产生的 🪞 section 仍然先留空，等下一轮。

### Step 5.5: 配图与原始图片归档

**原始作业照片**：Step 2 解析完照片后，**立即把原件 cp 到 `图片/原始图片/{UNIT_TOPIC}_{INDEX}_{SUBINDEX}.png`**，以防 image cache 被清理（实测 Claude Code 的 image cache 会定期清理，老照片可能已经丢失）。

**配图生成**：按 `references/image-generation.md` 调 `baoyu-danger-gemini-web` 生成：

- **核心知识点图解** 1 张（本次核心概念可视化，存到 `图片/核心知识点图解/{UNIT_TOPIC}_{知识点}.png`）。若该知识点图解已存在（跨批次共享）可复用，不重复生成。
- **错题图** N 张（每道新错题一张，存到 `图片/错题/{UNIT_TOPIC}_{知识点}.png`）。若相同知识点已有图可共享时也可复用。
- **数学建模课配图**（多张，规则见 `references/math-modeling-class.md` §6）：
  - 必画 3 张 —— 建模主图 / 抽象图 / 核心建模图（对应三步法的三块 callout 和主图位置）
  - 按需 2 张 —— 求解图 / 奥赛压轴题图
  - 全部存到 `图片/建模/{UNIT_TOPIC}_{主题关键词}_{图位}.png`
  - 风格按 `image-generation.md` 的阶段适配；视觉语言按主攻素养维度挑选（M1 抽象→左右分栏、M2 推理→逻辑链、M3 想象→立体格点、M4 归纳→表格+规律、M5 迁移→双图并排）
- **总结图**（仅跨周期触发时）

Cookie 过期先跑 `--login`；单张失败重试一次；连续 5 次失败放弃配图但不阻塞批改正文。

**配图失败时的 Markdown 降级**：批改记录 / 错题本 / 总结的模板里有 `![[xxx.png]]` 嵌入点。某张图最终没生成，对应位置**不嵌入 wikilink**，改成以下占位 callout（避免 broken link）：

```markdown
> [!note] 本题配图生成失败
> 配图流水线这次没跑通，不影响讲解。家长可以手动重触发再生成。
```

写回前必须校验：每个 `![[*.png]]` 引用的文件实际存在于 vault；否则替换为上面占位。

### Step 6: 写回 Obsidian

所有写入统一用 `obsidian create path="..." content="..." [overwrite] silent`：

- **新建**（无 overwrite）：**批改记录（简洁 + 完整 + 数学建模三份都必须产出）**、练习题、专题总结、里程碑
- **覆盖**（加 overwrite）：孩子档案、索引、回访队列、周/月/年报
- **追加**：错题本用"读-拼接-覆盖"模式（读出来→在内存里拼接新错题→覆盖写回）。obsidian-cli 的 `append` 命令不可靠

**大文件后备方案**：如果 `obsidian create` 因 content 过大而失败或超时（完整模式批改记录常 > 1000 行），改用文件系统直接 `cp /tmp/xxx.md <vault 根>/<相对路径>`。内容先写到 `/tmp/` 的 .md 文件，再 `cp` 到 vault 对应目录即可。

图片在 Step 5.5 已经直接 `cp` 到 vault 的 `图片/` 目录（二进制文件，绕过 obsidian-cli）。

写回内容要点：
- **批改记录（简洁 + 完整 + 数学建模必须同时写）**：
  - 简洁：5-callout 错题套装（为什么错 / 正确做法 / 验证 3 道）
  - 完整：8-callout 错题套装（再加 举一反三 / 容易混 / 小口诀 / 知识点延伸 / 正确题点评 / 技能诊断摘要）
  - 简洁 ↔ 完整末尾互相 wikilink；完整末尾 🔗 关联区加链到数学建模
  - 数学建模：建模主题 + 三步法 + 奥赛级练习题（折叠答案）+ 🔭 建模视角回顾；末尾链回简洁 + 完整
- 错题本：每道新错题一条，正文只用自然语言，技术 tag 进 frontmatter；链接指向**简洁版**批改记录（因错题本本身是简洁索引）
- 孩子档案：更新统计 / 节点命中数 / **建模思维图谱**（M1~M5 的近30天 + 累计计数、薄弱维度、均衡度）；**保留 `<!-- 家长备注开始 -->` / `<!-- 家长备注结束 -->` 之间内容**
- 索引 / 回访队列：纯覆盖
- 概念节点进入"掌握" → 追加专题文件；反思等级跃迁 → 追加里程碑文件

**历史记录不回填**：批改记录里的 `年龄 / 年级 / 认知阶段` 是当时的快照，不因孩子年龄变化而回改。档案是活数据，批改记录是历史数据。

### Step 7: 周 / 月 / 年总结

触发：
- Step 1 识别出**一个或多个**周期缺失 → 按最老周期起依次补齐
- 用户显式要求"总结本周 / 本月 / 今年"
- 节点掌握 → 追加专题总结
- 反思跃迁 → 追加里程碑

**缺失周期的补齐策略**（Step 1 已识别）：
- 按"周报 → 月报 → 年报"的层级依次补
- 同层级内按时间正序补（老的在前）
- 每份总结独立生成一张配图（`图片/总结/{周期}.png`），规则同 Step 5.5
- 无数据的周期仍要生成占位文件（不留空缺）

按 `references/summary-science.md` 出四维报告。正文用自然语言，frontmatter 保留技术字段。详细模板见 `references/summary-templates.md`。

### Step 8: 回应用户

- 整体情况：本次正确率、这次主要卡在哪、相比近期的一句话。
- Obsidian 中批改记录（简洁 / 完整）、数学建模专题课、练习题、回访题（若有）的 wikilink。
- 1~2 条家长侧建议：按年龄阶段取自 `pedagogy-by-stage.md`（活动 / 讨论题 / 复述题）。
- 简短介绍本次建模课的主题和第一道练习题，让家长和孩子知道今天"额外学了什么"。
- 关键字段缺失或冲突 → 在回应末尾列"待补充信息"。

## Failure Handling

- `obsidian-cli` 不可用或 Obsidian 未启动 → 停止并告知，不要只保留在对话中。
- 档案或回访队列读不到 → 首次运行就首次化；非首次运行停下来排查。
- `年龄` 字段缺失 → 阻塞式询问后回填；不要猜。
- 照片模糊或关键题目无法识别 → 批改能看清的部分，无法看清的标 `待确认` 并请求重拍。
- 照片多科目或多孩子 → 停下来询问本次聚焦哪个。
- 识别到非数学内容 → 明确拒绝。
- 到期回访 > 5 条 → 只处理 2 条（概念节点高优先），其余顺延。
- 孩子长期未上传（≥ 14 天）→ 把过期 ≥ 14 天的回访条目重置到 R1，在队列顶部加 `> [!warning]` 告知家长。
- 周 / 月 / 年周期内无批改 → 生成"本周期无数据"占位总结。
- 用户提供的年龄与档案差异大（> 2 岁）→ 停下来询问是否更新档案与阶段映射，不要静默覆盖（阶段切换影响讲解风格，必须显式确认）。
- 数学建模课生成失败（如 Claude 无法找到合适建模角度）→ 不阻塞批改主流程；在对话里告知家长，数学建模文件写入占位内容（含建模主题 + "本次建模课内容生成失败，请重新触发" 的 `[!warning]`）。
